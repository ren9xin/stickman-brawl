# 火柴人大乱斗 · Stickman Brawl

双人同屏 2D 对战原型。每一局的开局都是随机的——背景、出生点、陷阱位置、风向各不相同，玩家需要在不断变化的场地里用枪与法杖把对手打飞出场。

Unity（团结引擎）实现，C# 脚本 26 个 / 3681 行，单场景架构。

## 玩法

1. 主界面点击「开始」，播放按钮动画
2. 延迟 0.23 秒后进入游戏，同时触发生成流程：
   - 随机切换背景
   - 双角色随机出生点
   - 地面陷阱随机生成
   - 风场施加随机方向的外力
3. 双人同屏对战：移动、跳跃、开枪、施法
4. 命中造成扣血与击退，血量归零方判负
5. `GameState` 切入 `GameOver`，弹出结算界面显示获胜方图标
6. 点击「回到主界面」重置到 `StartUI` 状态

随机化是这一项目的核心设计：每局开始前，`随机背景`、`角色随机位置生成`、`刺刺生成`、`风控制` 四个模块同时启动，让同一个场景每次玩起来手感不同。

## 运行方式

1. 用团结引擎 1.8.1 或 Unity 2022.3.62f 系列版本打开工程
2. 打开 `Assets/Scenes/SampleScene.scene`，按 Play

场景 `SampleScene` 是唯一场景，双人操作需在同一键盘上完成。

> `Animator` 与 UI 引用全部挂在场景内对象上，打开场景后请勿删除根级管理器对象，否则运行时会因引用丢失报错。

## 技术实现

### 状态枚举驱动流程

`Assets/脚本/游戏状态.cs` 定义三态：

```csharp
public enum GameState
{
    StartUI,      // 主界面
    GamePlaying,  // 对战中
    GameOver      // 结算
}
```

单例持有当前状态，`Awake` 做重复实例销毁并 `DontDestroyOnLoad`。三个切换点分散在业务侧：`按钮.cs` 进入 Playing、`角色控制.cs` 在血量归零时进入 GameOver、`回到主界面.cs` 退回 StartUI。所有界面显隐、输入开关都以这个状态为唯一依据，避免多个布尔量互相打架。

### 随机化开局

四个生成器各自独立，通过协程错峰启动：

- **随机背景**：从候选背景池抽一张切换 `SpriteRenderer`
- **角色随机位置生成**：在候选出生点数组中取随机索引，双角色保证不重叠
- **刺刺生成**：按间隔在场地随机位置实例化陷阱
- **风控制**：周期性改变风力方向与强度，对角色刚体施加持续外力

协程统一用 `WaitForSeconds` 控制节奏，`DelayToStartGame(0.23f)` 让按钮动画播完再切场景逻辑，避免开局突兀。

### 战斗与判定

`角色控制.cs`（448 行）承担玩家 1 的全部行为：移动、跳跃、受击、击退、血量归零判定。受击时进入 `isKnocked` 分支，短暂禁用输入并施加反向冲量，让打击感有反馈。血量归零时把 `WinnerId` 写入全局单例并切状态：

```csharp
WinnerId = "Player2";
GameState.Instance.ChangeGameState(GameState.GameOver);
```

`游戏数据管理.cs` 在 `Update` 中监听 GameOver，关闭游戏主体、打开结算界面，调用 `胜利玩家.ShowWinner()` 按 `WinnerId` 显示对应图标。

### 分工明确的脚本结构

同一套行为被拆成角色 1 / 角色 2 两份控制脚本，武器拆成 `枪控制.cs`（弹道、射速、后坐力）与 `法杖控制.cs`（蓄力、咏唱、范围伤害），子弹行为独立在 `子弹控制.cs`。这种拆分让两个玩家的手感可以分别调参，不必在一个脚本里塞满 if 分支。

## 已知问题

- `结算界面.cs` 是空实现，结算实际靠场景内 GameObject 的 `Active` 切换完成。要改结算表现需同步改 `游戏数据管理.cs`，容易踩空。
- `按钮.cs` 中对 `血条1` / `血条2` 调用 `restart()` 前未做判空，场景内漏挂引用会在开局抛空引用异常（其余引用均有 `!= null` 判断）。
- 根级 `胜利图标.png` 4.3 MB、`9f3a33….png` 3.5 MB，未压缩，首次导入偏慢。
- `test.cs` 与 `角色控制.cs` 存在约 1400 行重复代码（相似度 0.82），是迭代过程中的试验副本，未清理。
- 无音频资源，打击音效缺失。
